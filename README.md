# 中国象棋 AI 人机对弈

基于极小化极大算法与 Alpha-Beta 剪枝的纯前端中国象棋人机对弈项目。

## 复刻声明

本仓库是 [shibing624/chinese-chess-ai](https://github.com/shibing624/chinese-chess-ai) 的复刻，用于继续维护和功能改进。本仓库只保留技术文档，不包含原作者的演示网站、联系方式等个人信息。

## 功能

- 完整象棋规则：支持将军、解将与将死判定；被将军时只能选择能解除威胁的走法。
- 智能 AI 对手：提供极速、标准、困难、大师四档检索难度，并从实力接近的候选走法中随机落子。
- 多维评估：综合棋子价值、位置、机动性、控制力和将军威胁等因素。
- 可选计时：可按需启用双方计时，休闲对局默认关闭。
- 智能提示：使用比当前难度更深的独立检索为玩家提供建议；低难度开局前三回合会进一步加深。
- 完整记录：走法历史记录，支持悔棋。

## 核心算法

### 极小化极大算法

```
function minimax(position, depth, maximizingPlayer):
    if depth == 0 or game_over:
        return evaluate(position)

    if maximizingPlayer:
        maxEval = -∞
        for each child of position:
            eval = minimax(child, depth - 1, false)
            maxEval = max(maxEval, eval)
        return maxEval
    else:
        minEval = +∞
        for each child of position:
            eval = minimax(child, depth - 1, true)
            minEval = min(minEval, eval)
        return minEval
```

### Alpha-Beta 剪枝优化

- 剪枝效率：最优情况下搜索节点数从 O(b^d) 降至 O(b^(d/2))。
- 迭代加深：在各档思考时间内逐层搜索，超时返回最后完整完成的一层。
- 搜索上限：由极速、标准、困难、大师四档难度控制。
- 移动排序：优先搜索吃子和强子移动，提高剪枝效率。
- 候选深化：浅层覆盖全部走法，深层集中检索排名靠前的候选。
- 走法变化：在分差合理的近优候选中加权随机选择，难度越高越偏向强招。

### 评估函数

| 评估维度 | 权重 | 说明 |
|---------|------|------|
| 物质价值 | 最高 | 将 10000、车 1000、炮 550、马 400、相/士 250、兵 150 |
| 位置价值 | 高 | 不同棋子在不同位置的战略价值 |
| 机动性 | 中 | 可移动位置数量，反映灵活性 |
| 控制力 | 中 | 威胁对方棋子的能力 |
| 将军威胁 | 高 | 进攻和防守将/帅的能力 |

## 使用说明

### 基本操作

1. 红方先行，玩家控制红方棋子。
2. 点击己方棋子进行选中。
3. 选中后显示可移动位置。
4. 点击高亮位置完成移动。
5. 点击对方棋子位置进行吃子。
6. 将军时状态区和玩家标签会显示将军；玩家被将死时可选择悔棋，AI 被将死则直接结束。

### 功能按钮

| 按钮 | 功能 | 说明 |
|------|------|------|
| 新游戏 | 重新开始 | 重置棋盘，开始新的对局 |
| 悔棋 | 撤销走法 | 撤销最近两步（玩家和 AI 各一步） |
| 提示 | 增强建议 | 比当前难度多检索一层；低难度开局前三回合再增加一层 |
| 音效 | 声音开关 | 开启或关闭游戏音效 |
| 难度 | 检索强度 | 可选择极速、标准、困难或大师 |
| 计时 | 对局时钟 | 可选的双方 15 分钟计时 |

### 音效系统

音效系统使用 Web Audio API 实时生成，包含：

- 选中音效：轻快的提示音（440Hz）
- 移动音效：清脆的落子声（330Hz）
- 吃子音效：低沉的碰撞声（220Hz）
- 将军音效：紧急警告音（880Hz）
- 胜利音效：上升旋律
- 失败音效：下降旋律
- 和棋音效：平稳音调
- 悔棋音效：倒退音效
- 新游戏：清脆开始音

## 自定义配置

### 调整 AI 难度

在页面的“难度”选项中选择极速、标准、困难或大师。标准为默认档位；更高档位拥有更长的思考时间、更深的搜索上限和更严格的近优筛选，但仍会保留少量走法变化。

### 自定义评估权重

在 `ai.js` 的 `evaluatePosition` 方法中调整：

```javascript
// 评估权重配置
const weights = {
    material: 1.0,      // 物质价值权重
    position: 0.3,      // 位置价值权重
    mobility: 0.2,      // 机动性权重
    control: 0.15,      // 控制力权重
    kingThreat: 0.4     // 将军威胁权重
};
```

## 常见问题

### AI 响应太慢怎么办？

在页面的“难度”选项中选择“标准”或“极速”，可以显著缩短等待时间。

### AI 太强或太弱怎么调整？

通过页面选项切换难度：“极速”适合快速体验，“标准”适合休闲对局，“困难”和“大师”适合更有挑战性的对局。

### 如何提高 AI 棋力？

1. 增加搜索深度（最直接）。
2. 优化评估函数权重。
3. 改进移动排序策略。
4. 添加开局库和残局库。

### 为什么选择纯前端实现？

- 部署简单，无需服务器。
- 响应速度快，无网络延迟。
- 隐私保护，数据不上传。
- 离线可用，随时随地对弈。

## 性能优化

- Alpha-Beta 剪枝：平均减少 60%-90% 的搜索节点。
- 移动排序：优先搜索有希望的走法，提高剪枝效率。
- 限时迭代：始终使用最后完整完成的搜索层，避免强行跑满深度。
- 后台计算：Web Worker 执行搜索，不阻塞棋盘和页面交互。
- 近优随机：根据难度加权选择质量接近的候选，减少固定套路。

## 算法性能

检索耗时取决于当前局面的可选走法数量及设备性能。各档设置了思考时间上限：极速和标准适合手机端快速对局，困难通常在约两秒内返回，大师最多思考约五秒。提示会在当前档位上增加一层搜索上限并使用更长的独立预算；极速和标准在开局前三个红方回合还会再增加一层，以减少浅层评分造成的固定炮路。复杂局面不强求跑满搜索上限，中残局分支减少后会自动完成更深层次。
